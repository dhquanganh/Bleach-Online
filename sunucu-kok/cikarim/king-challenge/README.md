# Tournament of Throne: registered players and byes

The active implementation has **no bots**. Players enter with the ??ng k? button and can update their saved formation before the cutoff. Registrations are shared across account workers in `.accounts/king-challenge.json`. Each level/reincarnation group accepts eight real entrants, kept in registration order; final seats are assigned only at the cutoff. A player cannot enter twice or change a formation after a wager has locked that entrant. The existing schedule remains Monday, Wednesday and Friday at 21:05 UTC+7.

At the start, a match with one entrant is a bye: the entrant advances immediately. Empty/empty branches are marked completed without a winner. This propagates through subsequent rounds, so the only registered player in a group becomes champion at kickoff without running combat or waiting for semifinal/final timers. Two real opponents use the registered combat-unit snapshots and the ordinary combat engine. For newly finalized groups, real matches begin 60/360/660 seconds after the registration deadline, leaving one minute to view the bracket and wager after pairing. Betting requires two real opponents; byes never charge wagers or fabricate replays.

`sunucu/king-challenge-store.js` uses a cross-process exclusive lock and atomic replacement. Successful account saves and registry commits publish the entry/results before emitting client notifications. Failed account saves do not publish registrations; failed registry commits restore the account state and refund debits. Results are shared and cannot reroll when another account views the bracket. `BLEACH_KING_CHALLENGE_FILE` optionally overrides the registry path for isolated tests.

Legacy bot brackets are removed from the active event when account state migrates to version 2. Previously earned, unclaimed rank prizes remain archived; unclaimed bot wager stakes are refunded once. Users explicitly register for the new event. Existing rank rewards, claim idempotency and offline reward retention remain in place. Recent genuine combat reports can be replayed; there is no battle report for a bye.

The client shows registration/update captions, registered status, a separate eight-slot registration roster, viewed-group occupancy, revised rules and missing opponents. The bracket, champion display and wagering controls remain hidden/disabled while registration is open. Champion rendering accepts an attacker or defender who won by default. Missing-opponent detail panels disable betting/replay and display the actual entrant instead of dereferencing a nonexistent opponent. The earlier layout repairs (final ButtonBar frame, scoped HUD/chat/pathfinding suppression) remain intact.

`build-registration.py` compiles the three incremental AS3 classes, checks unchanged non-code assets, re-exports the compiled code and publishes client **2026102320**, including bootstrap, manifest and launcher pointer. The previous builds/exports are preserved for review. No manual in-game rendering session has been run.

Client 2026102321 (build-close-detail.py) initializes the Fighting Detail close button during UIDispatch, once per window. Previously UpdateUI initialized it only after dereferencing both entrants, so early returns for a bye left the button unbound. The compiled class is re-exported to verify the binding is in UIDispatch and not recreated by refreshes. Closing only hides the window; the event refresh updates detail data only while it remains visible. Non-code assets are unchanged.

Client 2026102322 (patch-registration-phase.py and build-registration-phase.py) separates registration and competition. Open registration returns roster records and zero fight records, and stores no provisional bracket. The cutoff freezes/seeds each group exactly once in the shared registry, according to the final registration order. Updates retain list order. Holes are compacted during seeding. Old open-event preview boards/locks are discarded and pre-cutoff wagers refunded once; already-started legacy tournaments are not rewritten. Newly joining spectators see the active frozen tournament. Tests verify zero provisional matches, a frozen seven-match bracket at the cutoff, consistent late-spectator views, and the one-minute pre-combat betting window. Previous Fighting Detail close fix is preserved because this release changes only the main event window.
